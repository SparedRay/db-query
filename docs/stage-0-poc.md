**Goal:** a desktop SQL client that never freezes, for daily query work.
**Stack:** Tauri v2 (Rust backend) + vanilla TS/Vite frontend + CodeMirror 6.
**Status:** All phases (0-6) implemented. 70 unit + 21 live-server tests pass; build/clippy/rustfmt/tsc all clean. M1-M5 verified against MySQL 8.4; GUI click-through confirmed for M1-M4. v1 scope is complete.

## 1. Scope

### In scope (v1)
- One active connection at a time
- Database list populated on connect
- Schema tree expanded lazily (database → tables → columns)
- SQL editor with syntax highlighting and schema-aware autocomplete
- Advisory linting — warns, never blocks
- Run selection, or the statement under the cursor
- Run the whole buffer: multiple statements executed sequentially
- Result area with one tab per result set
- Result grid with row count and elapsed time
- Cancel a running query

### Explicitly out of scope (v1)
- Multiple simultaneous connections
- Editing result cells / write-back
- Multiple editor tabs
- Export to CSV/JSON
- Postgres or other engines
- Query history, saved queries, ER diagrams

> Rule for this project: if a feature isn't on the "in scope" list, it goes to the backlog, not into the weekend.

## 2. Architecture decisions

| Decision | Choice | Why |
|---|---|---|
| Shell | Tauri v2 | Small binary, Rust backend, native webview |
| Frontend framework | None (vanilla TS) | Three panels, no state tree worth a framework |
| Editor | CodeMirror 6 + `@codemirror/lang-sql` | Autocomplete, highlighting, selection handling for free |
| DB driver | `sqlx` (mysql, runtime-tokio) | Async, mature, connection pooling |
| Result transport | Whole set, capped at 5k rows | Simplest thing that works; windowed fetch is a later upgrade |
| Value representation | **Typed JSON** — numbers stay numbers, null stays null, rest stringified | Grid can align numerics and render NULL correctly for ~30 lines of decode |
| Row cap enforcement | **Auto-append `LIMIT 5000`** when a SELECT has none | Server never builds the huge set in the first place |
| Rewrite visibility | Show the effective SQL in the status bar when rewritten | Removes the "why doesn't this count match?" trap |
| Multi-statement | `run_script` returns `Vec<StatementResult>`, one tab per set | Auto-LIMIT only means anything per-statement |
| Statement splitting | Hand-rolled character scanner (quotes + comments aware) | A real parser is a project of its own; `;` splitting is too naive |
| Error behaviour | Stop at first error, return everything that already succeeded | Partial output matters when statement 3 of 5 fails |
| Cancellation | Second connection issuing `KILL QUERY <id>` | The actual fix for the Workbench problem |
| Schema data | Cached from `information_schema`, manual refresh | Never block the UI on introspection |
| Linting | Heuristics + schema checks, advisory only | A lint that blocks is a lint that's wrong at the worst moment |
| TLS mode | **rustls**, `VerifyIdentity` by default + explicit "allow invalid certs" toggle | Pure Rust, no OpenSSL C dependency. Secure by default; the toggle degrades to encrypted-but-unverified, never to plaintext |
| MySQL target | **8.0+ only** | Decided 2026-09-05. Modern `information_schema` shape, TLS defaults rustls accepts |
| Virtualized grid | **Hand-rolled** (~80 lines in `grid.ts`) | Keeps the dependency and licence-audit surface small; TanStack Virtual stays the fallback if it misbehaves |
| Licensing posture | Permissive-only dependency graph; no GPL source consulted | See §9 |

## 3. Backend command surface

Keep this stable — the frontend should only ever call these.

All commands return `Result<T, String>` — map `sqlx::Error` to a readable message at the boundary. All structs derive `Serialize`/`Deserialize` with `#[serde(rename_all = "camelCase")]` so the TS side gets idiomatic field names.

```rust
connect(config: ConnConfig)        -> Result<ConnInfo>      // + list of databases
disconnect()                       -> Result<()>
use_database(db: String)           -> Result<()>            // issues USE, updates session
list_tables(db: String)            -> Result<Vec<TableRef>>
list_columns(db, table)            -> Result<Vec<ColumnInfo>>
split_sql(sql: String)             -> Result<Vec<StatementSpan>>  // for cursor detection + lint
run_script(sql: String)            -> Result<ScriptResult>
cancel_query()                     -> Result<()>
```

```rust
struct ConnConfig {
    host: String,
    port: u16,                        // default 3306
    user: String,
    password: String,                 // in memory only — v1 does not persist credentials
    database: Option<String>,
}

struct ConnInfo {
    server_version: String,
    databases: Vec<String>,
    current_database: Option<String>,
}

struct TableRef  { name: String, kind: String }   // "BASE TABLE" | "VIEW"
struct ColumnInfo { name: String, data_type: String, nullable: bool, key: Option<String> }

struct ColumnMeta { name: String, type_hint: TypeHint }   // Numeric | Text | Temporal | Binary
struct StatementSpan { start: usize, end: usize }         // byte offsets into the buffer

enum StatementKind {
    Select,        // eligible for auto-LIMIT
    RowReturning,  // SHOW / DESCRIBE / EXPLAIN — returns rows, never rewritten
    Modify,        // INSERT / UPDATE / DELETE / REPLACE
    Other,         // DDL, SET, USE, everything else
}

struct ScriptResult {
    statements: Vec<StatementResult>,
    total_elapsed_ms: u64,
    aborted_at: Option<usize>,        // index of the statement that errored
}

struct StatementResult {
    sql: String,                      // the statement as written
    effective_sql: Option<String>,    // Some(..) only when we rewrote it
    kind: StatementKind,              // Select | Modify | Other
    outcome: Outcome,
    elapsed_ms: u64,
}

enum Outcome {
    Rows { columns: Vec<ColumnMeta>, rows: Vec<Vec<CellValue>>, truncated: bool },
    Affected(u64),
    Error(String),
}

#[derive(Serialize)]
#[serde(untagged)]
enum CellValue {
    Null,                             // -> JSON null
    Int(i64),
    Float(f64),
    Bool(bool),
    Text(String),                     // dates, decimals, blobs-as-<binary>, everything else
}
```

> **BIGINT hazard:** JS numbers lose precision above 2^53. Any integer outside `±9_007_199_254_740_991` must be emitted as `Text`, not `Int`, or IDs will silently corrupt in the grid.

**Session state.** **Corrected during implementation.** A single
`Mutex<Option<Session>>` holding both connections *deadlocks*: `run_script`
holds the lock for the whole query, so `cancel_query` can never acquire it to
send `KILL QUERY` — cancellation, the entire point of M5, could not work.
The two connections therefore live behind **separate mutexes**:

```rust
struct AppState {
    exec: Mutex<Option<MySqlConnection>>,   // held for the duration of a query
    ctl:  Mutex<Option<Control>>,           // taken briefly; free during a query
    running: AtomicBool,
    cancel_requested: AtomicBool,           // makes a script abandon its remainder
}

struct Control {
    killer: MySqlConnection,          // idle, exists only to issue KILL QUERY
    exec_conn_id: u64,                // from SELECT CONNECTION_ID() on `exec`
    current_db: Option<String>,
    schema_cache: HashMap<String, DbSchema>,
    host_label: String,
}
```

**Lock order is always `exec` then `ctl`, never the reverse.** `cancel_query`
takes only `ctl`, so it runs while `run_script` holds `exec`.

Use two dedicated `MySqlConnection`s, **not a `MySqlPool`**. A pool hands out arbitrary connections, so the `CONNECTION_ID()` you captured may not be the one running your query — and `KILL QUERY` would target the wrong session. Session state (`USE db`, temp tables, variables) also has to persist across statements, which a pool doesn't guarantee.

- [x] Tier 2 — schema-aware, from the autocomplete map:

**Implemented in Rust, not the frontend.** The linter reuses the execution
scanner (so "inside a string" means exactly what it means to the splitter) and
reads the schema cache directly. It needed one new mask variant:
`mask_keep_idents` preserves backticked identifier *contents* so `` FROM `users` ``
still yields a table name, while the strict `mask_noncode` continues to hide a
column called `` `limit` `` from auto-LIMIT detection. Same scanner, two
questions. Diagnostics carry byte offsets; the frontend converts to UTF-16
indices before handing them to CodeMirror.

**False-positive discipline.** Unqualified-column checking only fires when
exactly one table is in scope *and* the statement has no subquery. Function
calls, `AS` aliases, and a ~140-entry keyword list are all excluded. There are
9 dedicated false-positive guard tests, because the failure mode that matters
here is crying wolf, not missing a typo.

**Deliberately not doing:** full parse via `sqlparser-rs`. It doesn't cover every MySQL extension, so it would flag valid SQL as broken — and a linter that cries wolf gets ignored within a week.

## 6. Risks / things to watch

- **IPC payload size.** 5k rows × wide columns can get chunky over Tauri IPC. If it drags, that's the signal to move to windowed fetch (`get_rows(offset, len)`), not to optimize serialization.
- **Type decoding.** MySQL BLOB, JSON, DECIMAL, and dates all need explicit arms in the `CellValue` match. Expect to iterate. DECIMAL stays Text deliberately — routing it through `f64` would quietly corrupt money values.
- **Silent SQL rewriting.** Auto-LIMIT changes what actually ran. The `effective_sql` field and the status-bar chip are what keep this honest — don't skip them, they're the whole mitigation. Aggregates without GROUP BY (`SELECT COUNT(*)`) return one row anyway, so the rewrite is harmless there, but be careful the detection doesn't trip on `LIMIT` appearing inside a subquery or a string literal.
- **Statement splitting is now load-bearing.** It gates auto-LIMIT, result tabs, and statement-under-cursor. If the scanner mis-splits, you silently run the wrong SQL — which is worse than a freeze. Unit-test it before trusting it, and keep one splitter shared by both execution and cursor detection so they can never disagree.
- **Memory across sets.** Ten statements × 5k rows each all live in memory at once. Fine in practice, but the cap is per-statement, not per-script — worth a total-row ceiling if you ever paste something pathological.
- **Cancellation mid-script.** `KILL QUERY` kills the *current* statement. **Decided: abort the remainder.** Matches the stop-at-first-error rule, and the usual workload is SELECTs where stopping early costs nothing. Revisit only if migration-style scripts become a use case.
- **`information_schema` on large servers.** Can be slow with thousands of tables. Always filter by schema, never enumerate globally.
- **Timeouts must not drop the future.** Cancelling a query by dropping its future abandons the connection mid-protocol and leaves it unusable for the rest of the session. `await_with_timeout` instead KILLs from the idle control connection and then lets the original future unwind. Covered by `the_connection_stays_usable_after_a_timeout`.
- **`information_schema` column-name case — bug found 2026-09-05.** MySQL 8 returns those column names UPPERCASED no matter how the query is written, and sqlx matches names case-sensitively. `try_get("table_name")` therefore failed for every row, `filter_map` dropped them all, and **the schema tree rendered empty with no error at all**. Fixed by aliasing every projected column (`table_name AS name`). Any new `information_schema` query must alias too.
- **A cancelled query is not necessarily an errored one — bug found 2026-09-05.** `KILL QUERY` on `SELECT SLEEP(30)` makes it return `1` rather than raising, so a cancelled single-statement script looked like an ordinary success and the UI showed no cancellation at all. `run_script` now derives `cancelled` from the `cancel_requested` flag after the loop, not just from an error outcome.

## 7. Notes for the implementing agent

**Build order.** Phases are dependency-ordered; 2b must land before 3. Suggested repo layout:

```
src-tauri/src/
  main.rs          commands, state registration
  session.rs       Session struct, connect/disconnect/use_database
  split.rs         statement splitter (+ its unit tests)
  exec.rs          run_script, auto-LIMIT, cancel
  decode.rs        CellValue / ColumnMeta from sqlx rows
  schema.rs        information_schema queries + cache
src/
  main.ts          wiring, keybindings
  editor.ts        CodeMirror setup, autocomplete, lint
  grid.ts          virtualized table + tabs
  sidebar.ts       schema tree
```

**Ground rules**
- Frontend never parses SQL. Boundary detection goes through the `statement_at_cursor` command, which runs the same `split.rs` scanner execution uses. An earlier draft duplicated the cursor logic in TypeScript; the dead-code warning on `statement_at` is what caught it.
- No `unwrap()` on anything derived from user input or network. Errors become `Result<_, String>` and surface in the UI.
- The splitter is the one component that gets real unit tests. Everything else is verified by the milestone checks.
- Frontend never parses SQL. If it needs statement boundaries, it calls `split_sql`. One splitter, one source of truth.
- Long operations never block the UI thread. `run_script` is `async`; the frontend shows in-flight state and the cancel affordance.

**Resolved 2026-09-05** (were "deliberately unresolved"):
- TLS: **rustls**, `VerifyIdentity` by default with an "allow invalid certificates" toggle in the connection form that drops to `Required` (encrypted, unverified) — never to plaintext.
- **MySQL 8.0+ only.** `information_schema` queries are still written conservatively, so adding 5.7 later is a small change, not a rewrite.
- Grid: **hand-rolled** virtualization in `grid.ts`.

**Still open:**
- Nothing blocking. Query timeout (Phase 6) and the linter (Phase 5b) are unstarted.

**Three standing rules for this project:**

1. **Never link `libmysqlclient`.** Oracle's official C connector is GPL-2.0 and
   its FOSS exception does not cover proprietary use — linking it would force
   GPL onto the whole product. `sqlx` reimplements the MySQL wire protocol in
   pure Rust, so the C connector never enters the build. Any future driver
   swap must be a protocol reimplementation, not a C binding.

2. **No GPL client source is consulted.** MySQL Workbench, HeidiSQL and
   phpMyAdmin are all GPL-2.0. Observing how they *behave* is fine — UI
   behaviour and ideas are not copyrightable — but copying or transcribing
   their *source* contaminates this codebase. DBeaver Community (Apache-2.0)
   is the safe one to read if a reference implementation is ever needed.

3. **Two known non-permissive components, both fine:**
   - **WebKitGTK (LGPL-2.1)** — Tauri's Linux webview, linked dynamically as a
     system library. Dynamic linking against LGPL is fine for a proprietary
     product. Windows uses WebView2 and macOS uses WKWebView, both OS-supplied.
   - **lightningcss (MPL-2.0)** — Vite 8's CSS transformer. Build-time only,
     never shipped in the bundle, and MPL copyleft is file-level, so it binds
     only if lightningcss's own source is modified. It is not.
